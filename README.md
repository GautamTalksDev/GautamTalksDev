## Selected work

### AEGIS
**Worksite safety detection and alarm running on device, on a real time operating system.**
`C++20` `QNX 8` `Raspberry Pi 5` `CMake cross compilation` `Next.js 14` `MongoDB Atlas`
<sub>Built at cuHacking 7.</sub>

The detection and alarm pipeline runs entirely on the device. There is no network in
the path between seeing an unsafe condition and making noise about it, because a safety
alarm that needs an API call to speak is not a safety alarm.

<details><summary><sub>how the timing is actually enforced</sub></summary>

Ordering guarantees come from `SCHED_FIFO` priority scheduling, with the alarm path
above audio, and I verified the behaviour with structured latency measurement rather
than assuming the scheduler did what I expected. Inter process communication runs across
four QNX processes using trivially copyable POD message structs, so no serialization
step and no allocator sits inside the critical path.

I also built mock event generators, load testers, and a chaos harness, which let the
cloud and dashboard layers be validated without the hardware present. That mattered more
than it sounds: it is what let the team work in parallel instead of queuing behind one Pi.
</details>

### HyperShift
**Plain English intent becomes deployed, monitored infrastructure. No DevOps work required from the user.**
`TypeScript` `Node.js` `Next.js 14` `Turborepo` `pnpm` `BullMQ` `Zod` `PostgreSQL` `CLI`
<sub>Team project, 2025.</sub>

A five stage autonomous pipeline, Architect then Builder then Sentinel then SRE then
FinOps, running on BullMQ for durable execution. Deployment approval gates mean nothing
reaches production without a human check, and the FinOps stage attributes cost per
deployment so a runaway agent shows up as a number rather than as a bill.

<details><summary><sub>what stops it doing something expensive and stupid</sub></summary>

Every service boundary is enforced by a shared type safe Zod contract in a pnpm and
Turborepo monorepo, so integration breakage surfaces at compile time instead of halfway
through a deploy. The developer surface is the product, not an afterthought: a CLI for
pipeline execution, workspace scoped isolation, usage metering, and a public observability
dashboard exposing per run traces. If you cannot see what a run did, you cannot trust it
with an account.
</details>

### MetaShift
**Multi tenant SaaS platform built end to end, including the commercial surface.**
`Node.js` `Express` `React` `Supabase` `PostgreSQL` `WebSockets` `JWT` `RLS` `Stripe`
<sub>Team project, 2025.</sub>

Real time conflict detection with automatic resolution, streamed over WebSockets. What
I am actually proud of is the unglamorous half: usage metering, Stripe billing hooks,
notification webhooks, audit logging, a public status page, and JSON and CSV export
endpoints. Happy path CRUD is the easy quarter of a SaaS.

<details><summary><sub>where tenant isolation lives</sub></summary>

In PostgreSQL, as workspace level row level security, alongside JWT and API key
authentication. Isolation enforced in application code depends on every future endpoint
remembering to enforce it, which means it depends on my memory, which is not a security
model. Putting it in the database removes the chance to get it wrong.
</details>

### Chronos Cloud
**Event driven real time platform ingesting 14 live third party APIs across four domains.**
`Python` `NATS` `MongoDB` `Next.js` `MapLibre` `Solace PubSub+` `Gemini` `Cerebras`
<sub>Technical lead, team of 4, uOttaHack 8.</sub>

Every upstream integration has a graceful fallback, so a third party outage degrades the
service instead of taking it down. With 14 external dependencies, assuming they are all
up is not optimism, it is a design defect. Human in the loop approval is required before
any system action executes.

<details><summary><sub>the lead part, which was not the code</sub></summary>

I divided ownership across backend, frontend, and integration boundaries so four people
could work in parallel without blocking each other. An Agile sprint compressed into 36
hours mostly tests whether you defined the interfaces early enough. We did, and that is
why it shipped.
</details>
